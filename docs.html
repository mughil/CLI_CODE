Using CLI_CODE

CLI_CODE is a registry of agent-native command-line interfaces. Point an AI agent at it and it can discover, install, and drive a CLI for the software it needs — no GUI in the loop.

Overview

Every entry in the registry is one CLI with a fixed contract: structured JSON output for agents, a human-readable mode for debugging, and a consistent set of subcommands. Two kinds of entry exist:

  • Harness CLIs — generated wrappers that drive real desktop software (Blender, FreeCAD, GIMP, OBS…) or local services through their own APIs.
  • Public CLIs — third-party or official command-line tools already published to npm, Homebrew, or similar, catalogued here so agents can find them the same way.

Install for agents

Add the meta-skill once; the agent then reads the registry and installs whatever a task needs. Works with Claude Code, OpenClaw, Nanobot, Codex, and other SKILL-compatible agents.

npx skills add HKUDS/CLI-Anything --skill cli-hub-meta-skill -g -y

Then prompt the agent:

Find an appropriate CLI in CLI_CODE and complete the task: <your task>

Personal toolkit

The same registry is usable by hand through a small Python client.

pip install cli-anything-hub
CommandWhat it does
cli-hub listBrowse the registry
cli-hub search <kw>Search by keyword
cli-hub install <name>Install a CLI from the hub
cli-hub info <name>Inspect one CLI
cli-hub update <name>Update an install
cli-hub uninstall <name>Remove an install

The registry

Open Registry to browse all entries. The page is fully client-side:

  • Search matches name, display name, description, and category as you type.
  • Harness / Public toggle and the category dropdown narrow the list.
  • Every column header sorts; click again to reverse.
  • Click a row to open a detail panel with install / update / uninstall commands (each has a copy button), requirements, entry point, and contributors.
  • Filters and the open entry are written to the URL — copy the address bar to share an exact view, e.g. registry.html?q=blender&kind=harness.

Capability matrices

A matrix (Matrices) is a capability-based plan for a whole workflow. It lists the intents in that workflow — "turn a brief into a storyboard", "encode the final cut" — and, for each, the provider CLIs that satisfy it. Hand one to an agent and it knows which tool to reach for at every step. Each CLI chip links to its registry entry.

Demos

The three cards on the home page show agents building real artifacts through generated CLIs:

  • FreeCAD — Curiosity Rover: an agent assembles a rover, publishing preview bundles and a replayable trajectory.
  • Blender — Orbital Relay Drone: a hard-surface model grows under a live preview loop, each stage pushing render-backed bundles.
  • draw.io — System Diagram: a full architecture diagram built and laid out from a text brief.

Only poster images are bundled in this build; drop matching .mp4 files into assets/demos/ and swap the <img> tags for <video> to make them play.

Catalog data

Nothing about the catalog is hardcoded in the pages. Four JSON files under data/ drive everything:

FileContents
registry.jsonHarness CLIs — { meta, clis[] }
public_registry.jsonPublic / third-party CLIs — same shape, richer install fields
matrix_registry.jsonCapability matrices — { meta, matrices[] }
registry-dates.jsonLast-updated date keyed by CLI name

Each CLI object uses these fields: name, display_name, description, category, version, requires, install_cmd, and optionally npx_cmd, update_cmd, uninstall_cmd, entry_point, package_manager, homepage, source_url, contributors[]. Edit the files and reload — the UI re-renders.

Deploy this site

Static, no build step. Serve the folder root with any host. Locally, fetch() needs HTTP:

python -m http.server 4173

A GitHub Actions workflow at .github/workflows/deploy-pages.yml publishes the repo root to GitHub Pages on every push to main. One-time setup: repo Settings → Pages → Source: GitHub Actions.
