Using CLI_CODE

CLI_CODE is a registry of agent-native command-line interfaces. Point an AI agent at it and it can discover, install, and drive a CLI for the software it needs — no GUI in the loop.

Overview

Every entry in the registry is one CLI with a fixed contract: structured JSON output for agents, a human-readable mode for debugging, and a consistent set of subcommands. Two kinds of entry exist:

  • Harness CLIs — generated wrappers that drive real desktop software (Blender, FreeCAD, GIMP, OBS…) or local services through their own APIs.
  • Public CLIs — third-party or official command-line tools already published to npm, Homebrew, or similar, catalogued here so agents can find them the same way.

Install for agents

Add the meta-skill once; the agent then reads the registry and installs whatever a task needs. Works with Claude Code, OpenClaw, Nanobot, Codex, and other SKILL-compatible agents.

npx skills add HKUDS/CLI-Anything --skill cli-hub-meta-skill -g -y

Then prompt the agent:

Find an appropriate CLI in CLI_CODE and complete the task: <your task>

Personal toolkit

The same registry is usable by hand through a small Python client.

pip install cli-anything-hub
CommandWhat it does
cli-hub listBrowse the registry
cli-hub search <kw>Search by keyword
cli-hub install <name>Install a CLI from the hub
cli-hub info <name>Inspect one CLI
cli-hub update <name>Update an install
cli-hub uninstall <name>Remove an install

Browse & search

Open Browse to search all entries. Everything runs client-side over data/clis.json:

  • Weighted search ranks by field: name 10, aliases 8, tags 6, summary/description 5, category 4, use cases 4, language 2, platform 2. Matches are highlighted; multi-word queries require every term to match.
  • Facets: source, category, platform, language, install method, difficulty (shown when data exists), and a Curated only toggle.
  • Sort by name, category, or verified date — click a header, click again to reverse.
  • Keyboard: / focus search, ↑↓ move, Enter open, Esc clear.
  • Every filter is written to the URL — share registry.html?q=mock&cat=testing and it reopens the same view.
  • Each row links to its tool page (cli.html?slug=<slug>): install methods, platforms, language, use cases, alternatives, and related tools. Favorites and recently-viewed are kept in your browser only.

Capability matrices

A matrix (Stacks) is a capability-based plan for a whole workflow. It lists the intents in that workflow — "turn a brief into a storyboard", "encode the final cut" — and, for each, the provider CLIs that satisfy it. Hand one to an agent and it knows which tool to reach for at every step. Each CLI chip links to its registry entry.

Demos

The three cards on the home page show agents building real artifacts through generated CLIs:

  • FreeCAD — Curiosity Rover: an agent assembles a rover, publishing preview bundles and a replayable trajectory.
  • Blender — Orbital Relay Drone: a hard-surface model grows under a live preview loop, each stage pushing render-backed bundles.
  • draw.io — System Diagram: a full architecture diagram built and laid out from a text brief.

Only poster images are bundled in this build; drop matching .mp4 files into assets/demos/ and swap the <img> tags for <video> to make them play.

Catalog data

Nothing about the catalog is hardcoded in the pages. A build step (npm run build) merges the upstream registry snapshots with a human-verified overlay and emits data/clis.json + data/meta.json, validated against schema/cli.schema.json. Derivation never invents domain facts — use cases, alternatives, difficulty and precise language come only from data/overlay.json.

FileContents
data/clis.jsonBuilt, normalized entries the site loads (generated)
data/meta.jsonFacet counts: categories, platforms, languages, install methods (generated)
data/overlay.jsonContributor-maintained verified facts, keyed by slug
data/registry.json, data/public_registry.jsonUpstream registry snapshots (harness + public), inputs to the build
data/registry-dates.jsonLast-verified date keyed by tool name, input to the build
data/matrix_registry.jsonCapability matrices for the Stacks page

A built entry follows schema/cli.schema.json: id, slug, name, aliases, summary, description, categories, tags, useCases, platforms, language, runtime, license, install[], examples[], repository, documentation, packageManagers, difficulty, alternatives, related, lastVerified. To add or correct facts for a tool, edit its block in data/overlay.json and run:

npm install
npm run build      # regenerate data/clis.json + data/meta.json
npm run check      # schema + cross-references + link integrity

Run & deploy

The shipped site is static, zero-dependency. fetch() needs HTTP, so serve the folder — do not open index.html directly:

npm install && npm run build
npx http-server -p 4173   # or: python -m http.server 4173

Paths are relative, so it also works served from a subpath such as /CLI_CODE/. The GitHub Actions workflow at .github/workflows/deploy-pages.yml builds, validates and publishes to GitHub Pages on every push to main. One-time setup: repo Settings → Pages → Source: GitHub Actions.
